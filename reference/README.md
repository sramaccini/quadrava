# Reference implementation

Implements the contracts in `../contracts` to demonstrate them and to serve as a test bench. **Not for production**: in-memory stores, development users, no high availability.

| Module | Port | Contract |
| --- | --- | --- |
| `bff` | 8080 | OIDC session with Keycloak, tokens server-side only |
| `registry` | 8081 | `registry.yaml` |
| `authz` | 8082 | `authz.yaml` |
| `telemetry` | 8083 | `telemetry.yaml` |

The BFF forwards the routes in `lowcode.bff.routes` with the user's token (renewed when it expires) and `traceparent`, without the browser's cookies or `Authorization`: `/registry` → registry, `/authz` → authorization, `/telemetry` → telemetry, `/api` → the application back end (in development `npm run demo-api` in `frontend/`, port 8084). It protects writes with CSRF (`XSRF-TOKEN` cookie, `X-XSRF-TOKEN` header), answers 401 to API calls without a session and 502 if the service does not respond. After login (`/bff/login?return=...`) it sends the user back only to the origins in `lowcode.bff.frontend-origins`; the root redirects to `lowcode.bff.home` (`LOWCODE_HOME`, normally the runtime). Logout (`POST /logout`) also closes the Keycloak session (OIDC logout with `id_token_hint`); to calls with `Accept: application/json` it responds `{"redirect": "<address>"}` instead of redirecting.

The registry (contract 0.4) validates every document against the same JSON Schemas as the front end (`frontend/projects/schema/src/lib/schemas`, copied into the jar by the build; a test checks that it gives the same verdict as Ajv on all the examples) and rejects invalid documents with the list of problems. Versions have a review status (draft → in review → approved or rejected): only someone with a role in `lowcode.registry.approver-roles` (`responsabile`, `amministratore`) can approve or reject, and never the author; in the environments of `lowcode.registry.protected-environments` (`collaudo`, `produzione`) only approved versions can be published, and a navigation only if the screens it cites are already published there (409 with `missingReferences` otherwise). `GET …/versions/{hash}/references?env=…` lists the screens a version refers to (navigation items, `navigate` steps, `link` nodes) and those missing in the environment; for screens it is only a warning, because links between screens often form cycles. Saving with `If-Match` succeeds only if nobody has saved in the meantime (412 otherwise). With `lowcode.registry.storage-dir` (variable `LOWCODE_REGISTRY_DIR`) the store is on disk: one folder per document, atomic writes, identifiers checked before they become paths. Besides screens, navigation and themes it keeps the translation catalogues (`messages`, one per language). The registry records the user name (`preferred_username`) as the author of versions, not Keycloak's internal identifier. The development realm (`idp/realm-lowcode.json`) also has the public client `lowcode-strumenti` (password grant only) for local scripts such as `publish-examples`: it must not be reproduced in a real realm.

The registry has a `senza-auth` profile to try editor and runtime locally without Keycloak (see the main README): no authentication, a warning in the log at start-up, never outside the developer's machine.

Commands: `mvn verify` to build and test everything (checked with JDK 21 and Maven 3.9.6); `mvn -pl authz spring-boot:run` (or `java -jar <module>/target/*.jar`) to start a module (Keycloak must be running: `cd idp && docker compose up`). Tried live on 13 October 2026 with Keycloak 26.8: login, permissions, data, writes with CSRF, logout.

A customer back end must pass the same contract conformance tests as this implementation. The kits are in `frontend/tools` and run with `npm run conformance:registry`, `conformance:authz` and `conformance:telemetry`: over HTTP they check the registry's saving, validation, If-Match, history, publication with ETag, protected environments and review (17 checks); capabilities, permission format, version and batch checks of authorization (11); OTLP payloads, errors and limits of telemetry (6). The reference services pass all of them; authorization and telemetry answer errors in Problem format (RFC 9457). The whole stack starts with `npm run stack` (see the main README).
