# Quadrava screen schema reference

> Generated by `frontend/tools/schema-docs.mjs` from `screen.schema.json`: do not edit by hand. After changing the schema: `npm run schema:docs`. Properties marked * are required. Explanations with examples are in the [component catalogue](component-catalogue.md).

## Properties common to all components

| Property | Type | Description |
| --- | --- | --- |
| `id` | id | Identifier in kebab-case. It does not change once published. |
| `visibleIf` | expression | CEL expression in double braces, for example {{can('orders.order.approve') && row.status == 'sent'}}. Available variables: user, state, params, row, form, value. Available function: can(permission). |
| `hiddenIf` | expression | CEL expression in double braces, for example {{can('orders.order.approve') && row.status == 'sent'}}. Available variables: user, state, params, row, form, value. Available function: can(permission). |
| `enabledIf` | expression | CEL expression in double braces, for example {{can('orders.order.approve') && row.status == 'sent'}}. Available variables: user, state, params, row, form, value. Available function: can(permission). |
| `readOnlyIf` | expression | CEL expression in double braces, for example {{can('orders.order.approve') && row.status == 'sent'}}. Available variables: user, state, params, row, form, value. Available function: can(permission). |
| `tooltip` | text | Help text shown on mouse hover or with the focus. Text only (never HTML); it can contain {{ }}. |
| `grow` | integer 0–12 | Inside a box: share of the free space the component takes compared with its siblings (0 or absent = only the space it needs). |
| `span` | integer 1–12 | Inside a grid: columns taken (1 if absent, never more than those of the grid). |
| `region` | `north`, `south`, `west`, `east`, `center` | Inside a border: the region of the component (center if absent). Several components in the same region are stacked. |

## Components

### `section`

| Property | Type | Description |
| --- | --- | --- |
| `title` | text | Title of the section, shown at the top; it can contain {{ }}, for example a translated text. |
| `components` * | list of component | Components contained in the section, arranged according to layout. |
| `layout` | `column`, `row` | Arrangement of the components: stacked (column, default) or side by side, wrapping when space runs out (row), for example several fields on one line. |

### `text`

| Property | Type | Description |
| --- | --- | --- |
| `text` * | text | Text to show; it can contain {{ }}. Never HTML. |
| `style` | `heading`, `body` | heading: title; body: normal text (default). |
| `format` | `plain`, `markdown` | plain (default): simple text. markdown: text formatted with the Quadrava restricted Markdown: paragraphs, headings (#, ##, ###), bulleted (-) and numbered (1.) lists, also nested, quotes (>), **bold**, *italic*, ~~strikethrough~~, `code`, [links](https://…). Never HTML: even a text coming from the data is safe. |

### `button`

| Property | Type | Description |
| --- | --- | --- |
| `label` * | text | Text of the button; it can contain {{ }}. |

### `filterBar`

| Property | Type | Description |
| --- | --- | --- |
| `bind` * | text | Path in the screen state, for example state.filters. |
| `fields` * | list of field | Filter fields: each one writes its value in the `bind` state, under its own name (for example state.filters.status). textarea and richtext become one-line text. |

### `table`

| Property | Type | Description |
| --- | --- | --- |
| `source` * | text | Name of the data source that provides the rows. |
| `columns` * | list of tableColumn | Columns of the table, in order: field, header, format. |
| `rowActions` | list of action | Actions on a row, in the last column: expressions see the row as `row`. |
| `sort` | object | Sorting. With server paging the service does it: the table writes { field, direction } in the `bind` state; otherwise it sorts the loaded rows in the page. |
| `selection` | object | Row selection: the keys of the chosen rows are in the `bind` state; bulk actions see the whole rows in `selection`. |
| `bulkActions` | list of action | Actions on the selected rows, above the table. Expressions see `selection` (list of the chosen rows). |
| `rowActionsInline` | integer 0–10 | How many (visible) row actions to show as buttons; the others go into the «⋯» menu. 0 = all in the menu; if missing, all buttons. |
| `expand` | object | Area that opens under the row: its nodes see the row as `row`. Data sources belong to the screen: inside the area the values of `row` are used. |
| `refreshable` | yes/no | «Refresh» button in the table footer, on the left (pages are on the right): it reloads the data source like the refresh step. Absent if false or not given. |

### `form`

| Property | Type | Description |
| --- | --- | --- |
| `source` | text | Name of the data source that provides the initial values (absent in entry forms). |
| `initial` | object | Initial values with expressions, resolved once when the screen opens; for example {"type": "{{params.type}}"}. |
| `fields` * | list of field | Fields of the form, in order. The values are read as `form` in expressions. |
| `actions` | list of action | Buttons under the fields: on click the form checks the visible fields and, if they are valid, runs the steps, which see the values in `form`. |
| `columns` | integer 1–4 | Columns of the field grid (1 if absent). With little space the form goes back to one column. |
| `validation` | list of formRule | Rules across fields, checked with those of the fields: each says the fields it checks (fields), and the message goes to them. For example [{ "after": "start", "fields": ["end"] }, { "sameAs": "email", "fields": ["emailConfirm"] }, { "atLeastOne": ["phone", "email"] }]. |

### `input`

| Property | Type | Description |
| --- | --- | --- |
| `field` * | field | The field to show, with the same properties as the form fields (type, label, options, required, validation rule, lookup, file…). The name identifies the field and, without `bind`, the value in the state. |
| `bind` | state path | State where the field reads and writes the value (state.<field name> if absent). The data sources that use it reload when it changes. |
| `default` |  | Initial value, if the state does not have one already (null if absent; false for checkbox and switch). Texts can contain {{ }}, for example a translated text. |
| `onChange` | list of step | Steps run after every change of the value, which see the new value in `value`. Free text is written to the state when leaving the field or with Enter. |
| `group` | text | Validation group: the step { "validate": "<group>" } checks the fields of the same group together. |

### `kanban`

| Property | Type | Description |
| --- | --- | --- |
| `source` * | text | Data source with the cards (a list of rows). |
| `columnField` * | text | Field of the row that decides the column (for example status). |
| `titleField` * | text | Field shown as the title of the card. |
| `descriptionField` | text | Field shown under the title of the card. |
| `keyField` | text | Field that identifies the card (id if absent): onMove receives the keys of the neighbours in beforeId and afterId. |
| `avatarField` | text | Field with the name of the person of the card (for example the assignee), shown as a round mark with the initials; the full name is in the tooltip and read by screen readers. |
| `badges` | list of object | Coloured labels on the card, for example priority and type (at most 4). |
| `footerFields` | list of object | Values at the bottom of the card, for example the story points or the due date (at most 4). |
| `columns` | list of object or expression | Columns of the board, in order (at most 10); or an expression that returns them as a list of {value, label, tone, limit}, for example {{ params.board == "bugs" ? [...] : [...] }}, so one screen serves several boards. In a CEL list all the values of a column are texts ('limit': '5'); labels returned by an expression are shown as they are. |
| `columnsFrom` | object | Columns read from a data source instead of `columns`, for boards whose columns are data (for example the statuses of a workflow). |
| `laneField` | text | Field of the row that decides the swimlane (for example the assignee): the board is divided into horizontal lanes that can be collapsed. A card moves only within its lane. |
| `lanes` | list of object | Lanes in order, with their headers; rows whose value is not a lane are not shown. Without it every value of `laneField` in the data is a lane, in order of appearance, and the cards without a value go to a last lane «No group». |
| `reorder` | yes/no | Cards can also change place within their column: they are dropped between other cards, or moved up and down from the «Move» menu, and onMove runs for these moves too (false if absent: only moves to another column). |
| `moveIf` | expression | Condition for moving a card (it sees the row in row), for example a permission. |
| `onMove` | list of step | Steps that move a card (usually call and refresh): they see the row in row, the starting column in from, the target one in to, and the keys (keyField) of the cards that will be before and after it in beforeId and afterId (null at the ends of the column). |

## Fields (forms, filters, standalone fields)

| Property | Type | Description |
| --- | --- | --- |

| `label` | text |  |
| `required` | yes/no |  |
| `options` | list of text |  |
| `sensitive` | yes/no | The value never appears in traces and logs. |
| `visibleIf` | expression | CEL expression in double braces, for example {{can('orders.order.approve') && row.status == 'sent'}}. Available variables: user, state, params, row, form, value. Available function: can(permission). |
| `hiddenIf` | expression | CEL expression in double braces, for example {{can('orders.order.approve') && row.status == 'sent'}}. Available variables: user, state, params, row, form, value. Available function: can(permission). |

| `maxLength` | integer 1–100000 | For text, textarea and richtext: maximum number of characters. |

| `format` | `email`, `url`, `phone`, `iban`, `bic`, `uuid`, `alphanumeric`, `vatNumber`, `taxCode`, `companyId`, `postalCode` | For text: expected format. email; url (http or https); phone (international, 6 to 15 digits, with + spaces dashes dots and brackets); iban (length of the country and check digits); bic; uuid; alphanumeric (letters A-Z and digits only); vatNumber (VAT number with its national check: IT, DE, FR, ES, NL, BE, AT, PT, PL, SE; without country the prefix of the number decides); taxCode (personal tax number: IT codice fiscale, ES NIF/NIE, PT NIF, NL BSN); companyId (IT partita IVA, FR SIREN/SIRET, ES CIF, PT NIPC, BE enterprise number, NL KvK); postalCode (IT, DE, FR, ES, NL, BE, AT, PT, PL, SE). | `minDate` | text | For date and datetime: earliest date allowed: YYYY-MM-DD (or YYYY-MM-DDTHH:mm), or relative to the day: today, today+30d, today-18y (units d, w, m, y). Earlier days cannot be chosen in the calendar. |

## Data sources

A REST call to a service of the application, through the BFF (relative address on the same origin).

| Property | Type | Description |
| --- | --- | --- |
| `type` * | `"rest"` | Kind of data source: rest. |
| `method` * | `GET`, `POST`, `PUT`, `PATCH`, `DELETE` | HTTP method: GET reads (when the screen opens and with refresh), the others write (with call). |
| `url` * | text | Address of the service, relative to the same origin (for example /api/orders); it can hold expressions. |
| `params` | object | Query parameters (GET, DELETE). |
| `body` |  | Request body (POST, PUT, PATCH): an object with expressions or a single expression, for example {{form}}. If missing, params is used. |
| `paging` | `server`, `none` | server: the table asks the service for one page at a time (page, size, sort, filters); none (default): all the rows at once. |

### Reference to a data source of the project

Reference to a data source of the project: the identifier of the data sources document and the name of the data source in it. params and body, if present, replace those of the referenced data source (params key by key).

| Property | Type | Description |
| --- | --- | --- |
| `ref` * | text | Document and name of the data source, separated by a slash: orders/list. |
| `params` | object | Query parameters added to those of the referenced data source (same name: this one wins). |
| `body` |  | Request body that replaces the one of the referenced data source: an object with expressions or a single expression. |

### Data sources document (`datasources.schema.json`)

Data sources of a project, shared by its screens: one document holds one or more of them (for example all the calls of the orders service). A screen uses one with a reference such as {"ref": "orders/list"} in its dataSources.

| Property | Type | Description |
| --- | --- | --- |
| `schemaVersion` * | `"1.0"` | Version of the format. |
| `datasources` * | text | Identifier of the document (kebab-case): the first part of the references, orders in orders/list. |
| `description` | text | What these data sources are for, for whoever chooses them in the editor. |
| `baseUrl` | text | Address put in front of the url of every data source of the document, for example /api/orders or {{ settings.ordersApi }}: the url of each data source is then the rest of the path (/{{ params.id }}). Relative to the same origin, as every url; none if missing. |
| `sources` * | object | The data sources, by name: the second part of the references, list in orders/list. |
