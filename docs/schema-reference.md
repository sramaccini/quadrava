# KinetiX screen schema reference

> Generated by `frontend/tools/schema-docs.mjs` from `screen.schema.json`: do not edit by hand. After changing the schema: `npm run schema:docs`. Properties marked * are required. Descriptions are in Italian, as KinetiX Studio shows them. Explanations with examples are in the [component catalogue](component-catalogue.md).

## Properties common to all components

| Property | Type | Description |
| --- | --- | --- |
| `id` | id | Identificativo in kebab-case. Una volta pubblicato non cambia. |
| `visibleIf` | expression | Espressione CEL tra doppie graffe, per esempio {{can('ordini.ordine.approva') && row.stato == 'inviato'}}. Variabili disponibili: user, state, params, row, form, value. Funzione disponibile: can(permesso). |
| `hiddenIf` | expression | Espressione CEL tra doppie graffe, per esempio {{can('ordini.ordine.approva') && row.stato == 'inviato'}}. Variabili disponibili: user, state, params, row, form, value. Funzione disponibile: can(permesso). |
| `enabledIf` | expression | Espressione CEL tra doppie graffe, per esempio {{can('ordini.ordine.approva') && row.stato == 'inviato'}}. Variabili disponibili: user, state, params, row, form, value. Funzione disponibile: can(permesso). |
| `readOnlyIf` | expression | Espressione CEL tra doppie graffe, per esempio {{can('ordini.ordine.approva') && row.stato == 'inviato'}}. Variabili disponibili: user, state, params, row, form, value. Funzione disponibile: can(permesso). |
| `tooltip` | text | Testo di aiuto mostrato al passaggio del mouse o con il focus. Solo testo (mai HTML); può contenere {{ }}. |
| `grow` | integer 0–12 | Dentro un box: quota dello spazio libero che il componente prende rispetto ai fratelli (0 o assente = solo lo spazio che gli serve). |
| `span` | integer 1–12 | Dentro una griglia: colonne occupate (1 se assente, mai più di quelle della griglia). |
| `region` | `north`, `south`, `west`, `east`, `center` | Dentro un border: la regione del componente (center se assente). Più componenti nella stessa regione stanno uno sotto l’altro. |

## Components

### `section`

| Property | Type | Description |
| --- | --- | --- |
| `title` | text | Titolo della sezione, mostrato in testa; può contenere {{ }}, per esempio un testo tradotto. |

| `layout` | `column`, `row` | Disposizione dei componenti: uno sotto l’altro (column, predefinito) o affiancati e a capo quando manca spazio (row), per esempio più campi in una riga. |

### `table`

| Property | Type | Description |
| --- | --- | --- |
| `source` * | text | Nome del data source che fornisce le righe. |
| `columns` * | list of tableColumn | Colonne della tabella, in ordine: campo, intestazione, formato. |
| `rowActions` | list of action | Azioni su una riga, nell’ultima colonna: le espressioni vedono la riga come `row`. |
| `sort` | object | Ordinamento. Con paging server lo fa il servizio: la tabella scrive { field, direction } nello stato `bind`; altrimenti ordina in pagina le righe caricate. |
| `selection` | object | Selezione delle righe: le chiavi delle righe scelte stanno nello stato `bind`; le azioni multiple vedono le righe intere in `selection`. |

| `rowActionsInline` | integer 0–10 | Quante azioni di riga (visibili) mostrare come pulsanti; le altre finiscono nel menu «⋯». 0 = tutte nel menu; se manca, tutte pulsanti. |
| `expand` | object | Area che si apre sotto la riga: i nodi vedono la riga come `row`. I data source sono della schermata: dentro l'area si usano i valori di `row`. |
| `refreshable` | yes/no | Pulsante «Aggiorna» nel piede della tabella, a sinistra (le pagine sono a destra): ricarica il data source come il passo refresh. Assente se false o non indicato. |
